# TimeFarm v0.2.3 — Cloud-enabled Windows prerelease

TimeFarm v0.2.3 is the first cloud-enabled candidate for the offline-first
Windows time tracker, project timer, and freelancer earnings analytics app.
This document describes the candidate; the release is not published until the
protected GitHub workflow creates the installer and all runtime gates pass.

## Release safety

- Windows 10/11 x64, packaged as a per-user NSIS installer.
- Unsigned v0.x prerelease: Authenticode must report `NotSigned`, so Windows may
  show **Unknown Publisher** or a SmartScreen warning.
- Verify the published `SHA256SUMS.txt` before running the installer.
- The installer contains only the public Supabase origin and a dedicated
  publishable desktop key. It contains no `service_role`, secret key, database
  password, personal access token, or OAuth client secret.
- The GitHub release must also include an SPDX SBOM plus SBOM and build-provenance
  attestations for the exact installer.

## Highlights

### Offline-first timer and earnings analytics

- Start, pause, resume, recover, and complete work even when the network is
  unavailable.
- Keep projects, completed work, payments, goals, preferences, sync metadata,
  and conflicts in a local SQLite database.
- Preserve earnings in their original currency and calculate time using stored
  timestamps, pause intervals, and timezone-aware day boundaries.
- Review Dashboard, Projects, History, Analytics, Profile, Settings, and the
  native mini timer through the Quiet Instrument interface.

### Google sign-in and Supabase synchronization

- Email/password and Google OAuth run through the Electron main process; bearer
  tokens are not exposed to the renderer.
- Google is configured as External / In production.
- Google authorized redirect URI:
  `https://kyjswjvuveiiwuysobaa.supabase.co/auth/v1/callback`
- Supabase additional desktop redirect:
  `timefarm://auth/callback?timefarm_state=**`
- The desktop flow uses PKCE plus a TimeFarm nonce, persists an encrypted
  continuation for one bounded restart, and accepts only the exact callback.
- Sync uses empty-device bootstrap, atomic workspace claim, pull-before-push,
  durable idempotent outbox operations, optimistic revisions, bounded reads,
  explicit conflicts, and a conservative online timer lease.

### Production database hardening

- Production is current through migrations `0001`–`0008`.
- Migration `0008_timer_lease_privileges.sql` revokes inherited `PUBLIC` and
  direct `anon` execution from the timer-lease RPC while retaining
  `authenticated` access.
- A fresh CI replay passes schema lint and 105 pgTAP assertions (`61 + 44`).
- The hosted contract passes 6/6 RPC existence and unauthenticated-denial
  probes against production.
- Production uses a dedicated publishable desktop key; legacy anon and
  service-role API-key headers are disabled.

### Reliability and desktop hotfixes

- Local timer mutations do not wait for authentication or network sync.
- In-flight cloud operations remain durable across crashes and ambiguous
  timeouts, and edits made during a push remain queued as successors.
- Cache rebuild and device wipe reject unsettled work; sign-out cancels late
  sync writes and verifies encrypted credential removal.
- Profile and Settings remain interactive on desktop while the responsive
  account menu stays hidden when closed on mobile.

## Remaining release gates and limitations

- Complete installed-app Google PKCE must be verified through the system browser
  and exact `timefarm://` return, including restart, cancellation, expiry, and
  provider-error paths.
- Workspace claim/link and authenticated production sync push/pull must be
  verified without wiping existing local data.
- Conflict handling, authenticated lease acquisition/renewal, and competing
  physical devices remain unverified. Do not describe v0.2.3 as a proven
  multi-device timer until those tests pass.
- Clean-machine upgrade/rollback, long network/provider outages, physical screen
  readers, high-DPI/multi-monitor behavior, crash/power-loss recovery, and an
  automatic update channel need broader real-device validation.
- This prerelease is intentionally unsigned and has no established SmartScreen
  reputation. Code signing remains deferred to a future stable release line.
